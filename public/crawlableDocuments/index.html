Comprehensive Survey of Document-Discovery Techniques in Focused Web Crawlers

A. Sharma, B. Krishnamurti, C. Osei-Bonsu, D. Lindqvist

Angaadi Institute of Information Retrieval  ·  Technical Report ARF-2024-04

Abstract

Modern focused crawlers must reliably discover documents of diverse formats across heterogeneous web deployments. This survey examines link-extraction strategies over corpora spanning PDFs, plain-text standards documents, and structured markup formats. The baseline corpus includes the canonical sample reference PDF from Africau University, the Internet Engineering Task Force specification RFC 791 (Internet Protocol) as a plain-text baseline, and the Project Gutenberg edition of Pride and Prejudice as a large prose corpus. Together these three anchors exercise the most common MIME types a production crawler will encounter.

We further analyse edge cases introduced by case-insensitive file extensions, query-string parameters that carry version metadata, and URL-encoded extension characters that naive parsers misclassify. Reproducibility artifacts are available through the access panel on the right.

3 · Query Strings and Fragments

Version metadata appended as query parameters and anchor fragments must not confuse the extension extractor. All three links below point to a supported format.

  • https://www.africau.edu/images/default/sample.pdf?version=2&lang=en — query string appended to .pdf
  • https://www.africau.edu/images/default/sample.pdf#page=3 — fragment appended to .pdf
  • https://www.rfc-editor.org/rfc/rfc791.txt?download=true — query string appended to .txt

4 · Tricky Paths — Parser Edge Cases

These three URLs exercise pathological patterns that naive extension-matching regexes misclassify. A robust crawler should handle all three correctly.

4.1   Extension in a Middle Path Segment

  • https://www.irs.gov/forms.pdf/archive/f1040 — ".pdf" in a path segment; final segment has no extension

4.2   Extension Only in a Query Parameter

  • https://www.irs.gov/view?file=report.pdf — ".pdf" is a query-param value, not the path extension

4.3   Percent-Encoded Extension

  • https://www.africau.edu/images/default/sample%2Epdf — dot before "pdf" is percent-encoded as %2E; parsers must decode before matching
